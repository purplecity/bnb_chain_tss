# 安全边界和上线前检查

本仓库是可测试原型，不是经过独立密码学审计的生产托管系统。上线前需由熟悉 tss-lib 和 MPC 的安全团队审查代码、依赖版本、部署流程和威胁模型。

## 私钥导入方案

`task1-keygen` 使用 tss-lib `vss.Create` 以输入私钥为多项式常数项生成 Feldman VSS shares；它不是分布式仪式，完整输入私钥和三份 share 在同一离线进程内可用。为了用于 tss-lib ECDSA 签名，程序还需将 VSS 结果与 tss-lib 生成的三组 Paillier/safe-prime 预参数组装成 `LocalPartySaveData`。该组装直接对应当前 v4 save-data 字段，但仍需审计，且只完成了本地保存结构，并不证明在线 signer 间完成过分布式 keygen。若离线机被攻破，攻击者可能拿到完整私钥。

## 分片泄露

`share.json` 包含 Xi 和 Paillier 秘密参数，是高敏感凭据。0600 权限只是基础保护，不等于加密。每个节点只保留自己的份额；传输与备份必须逐份隔离，避免共享日志、崩溃转储或信任域。节点最好运行在独立主机、云账号、网络区和运维权限下。

reshare 可以更新份额，正常情况下保持根公钥不变，因此不会撤销攻击者已经复制的旧份额。若有完整私钥泄露迹象、门限份额同时被攻破或签名机失陷，应视为根密钥泄露：生成新的根公钥/钱包并迁移链上资产；仅重新分片不能让旧公钥失效。

## 签名策略

网关接受任意 32 字节 digest。API key 只认证调用方，不表达交易授权。部署前应在可信策略层解析并验证链 ID、交易类型、收款人、金额、token、nonce、费用和业务审批；高风险操作应有多角色批准、额度和速率限制。当前队列在内存中，重启会丢作业，不能作为持久交易账本。

Signer gRPC 和 gateway API 默认使用明文连接，因为连接证书是可选项。明文连接不提供加密或对端认证，必须放在隔离的私有网络并配置严格防火墙。流量跨越网络边界时启用可选的双向 TLS 和证书 pin。API key 只认证 gateway 调用方，不能保护 signer 之间的流量。

## 地址派生

路径 `m/site_id/index` 两级都是非硬化，每级小于 `2^31`。拿到根公钥和 chain code 的人可以枚举派生公钥和地址；这是公开充值地址设计的属性，不会泄漏私钥本身。必须避免索引复用并限制谁可修改映射。

## 上线前验证

固定并审计具体 tss-lib commit；执行全量集成测试；在隔离网络验证可选证书 pin、节点断连、超时、节点重启、重复请求和队列满载；演练备份恢复与应急迁移；加入指标、审计、告警、访问控制和交易策略。未经审核不要直接用于真实资金。
